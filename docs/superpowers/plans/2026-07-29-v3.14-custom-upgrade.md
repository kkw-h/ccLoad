# ccLoad v3.14 定制版升级实现计划

> **面向 AI 代理的工作者：** 必需子技能：使用 superpowers:subagent-driven-development（推荐）或 superpowers:executing-plans 逐任务实现此计划。步骤使用复选框（`- [ ]`）语法来跟踪进度。

**目标：** 将官方 ccLoad v3.14.0 集成到现有外部鉴权定制版，并安全部署到 YiSuo 中转站。

**架构：** 以包含外部鉴权的 `origin/master` 为基线，通过 Git merge 引入官方
`v3.14.0`。验证完整源码后交叉编译 Linux amd64 二进制，使用服务器端备份和原子
替换完成滚动升级。

**技术栈：** Go、Gin、PostgreSQL、Node.js tests、Git、systemd、SSH

---

## 文件结构

- `docs/superpowers/plans/2026-07-29-v3.14-custom-upgrade.md`：记录升级执行步骤。
- 合并产生的源码文件：由 `git merge v3.14.0` 精确确定；只处理官方升级与外部
  鉴权定制功能的真实冲突，不做无关重构。
- `ccload-linux-amd64-v3.14.0-custom`：本地构建产物，不提交 Git。

### 任务 2：合并官方 v3.14.0

- [ ] **步骤 1：确认升级边界**

运行：`git log --oneline --decorate origin/master..v3.14.0`
预期：仅显示官方 v3.13.2 至 v3.14.0 的升级提交。

- [ ] **步骤 2：合并官方标签**

运行：`git merge --no-ff v3.14.0 -m "merge: upgrade custom build to v3.14.0"`
预期：合并完成；如有冲突，仅保留官方新行为与现有外部鉴权行为的组合。

- [ ] **步骤 3：审查合并结果**

运行：`git status --short && git diff --check HEAD^1..HEAD`
预期：工作区干净且无空白错误。

### 任务 3：验证合并版本

- [ ] **步骤 1：运行外部鉴权定向测试**

运行：`go test -tags sonic ./internal/app -run 'ExternalAuth|ProxyRoutesUseExternalAuth' -count=1`
预期：外部鉴权开关、环境路由、CIDR 绕过及本地 Token 衔接测试全部通过。

- [ ] **步骤 2：运行完整 Go 测试**

运行：`go test -tags sonic ./internal/...`
预期：全部包通过，退出码 0。

- [ ] **步骤 3：运行 Web 验证**

运行：`make verify-web`
预期：全部前端测试通过，退出码 0。

### 任务 4：构建生产二进制

- [ ] **步骤 1：确定定制版本字符串**

运行：`git rev-parse --short HEAD`
预期：获得 7 位合并提交短 SHA，用于形成定制版本字符串。

- [ ] **步骤 2：交叉编译 Linux amd64**

运行：`upgrade_sha=$(git rev-parse --short HEAD); upgrade_time=$(date '+%Y-%m-%d %H:%M:%S %z'); CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -tags sonic -trimpath -ldflags "-s -w -X ccLoad/internal/version.Version=v3.14.0-custom-${upgrade_sha} -X ccLoad/internal/version.Commit=${upgrade_sha} -X 'ccLoad/internal/version.BuildTime=${upgrade_time}' -X ccLoad/internal/version.BuiltBy=codex" -o ccload-linux-amd64-v3.14.0-custom .`
预期：退出码 0，生成 ELF 64-bit x86-64 二进制。

- [ ] **步骤 3：验证构建产物**

运行：`file ccload-linux-amd64-v3.14.0-custom && shasum -a 256 ccload-linux-amd64-v3.14.0-custom`
预期：架构为 x86-64，并输出 SHA-256。

### 任务 5：部署和验收

- [ ] **步骤 1：记录升级前状态**

运行：`ssh YiSuo中转站 'systemctl is-active ccload && curl -fsS http://127.0.0.1:8080/public/version'`
预期：服务为 active，版本为当前 `v3.13.3-custom-ce0604f`。

- [ ] **步骤 2：上传临时二进制**

运行：`scp ccload-linux-amd64-v3.14.0-custom YiSuo中转站:/tmp/ccload-v3.14.0-custom`
预期：上传成功。

- [ ] **步骤 3：备份并原子替换**

运行：`ssh YiSuo中转站 'test ! -e /usr/local/bin/ccload.backup.20260729-v3.14-upgrade && sudo install -m 0755 /usr/local/bin/ccload /usr/local/bin/ccload.backup.20260729-v3.14-upgrade && sudo install -o root -g root -m 0755 /tmp/ccload-v3.14.0-custom /usr/local/bin/ccload && sudo systemctl restart ccload'`
预期：命令退出码 0。

- [ ] **步骤 4：验证服务**

运行：`ssh YiSuo中转站 'systemctl is-active ccload; curl -fsS http://127.0.0.1:8080/health; curl -fsS http://127.0.0.1:8080/public/version; journalctl -u ccload -n 30 --no-pager'`
预期：服务 active，健康接口成功，版本为 `v3.14.0-custom-*`，日志无启动错误。

- [ ] **步骤 5：验证本地 SSH 代理**

运行：`curl -fsS http://127.0.0.1:18080/public/version`
预期：通过现有隧道获得同一 `v3.14.0-custom-*` 版本。

- [ ] **步骤 6：失败时回滚**

仅当步骤 3 至 5 失败时运行：
`ssh YiSuo中转站 'sudo install -m 0755 /usr/local/bin/ccload.backup.20260729-v3.14-upgrade /usr/local/bin/ccload && sudo systemctl restart ccload'`
预期：恢复旧版本且 `/health` 再次成功。
